# skill-radar v2.2 设计：add 安全网关 + 托盘守护客户端（Windows + macOS）

状态：待实现 · 日期：2026-10-03 · 来源：第二轮 grilling 全部按推荐 + 用户三项修正
（Q3 选 c 只做托盘版；界面调用本地前端技能做美观；macOS 必须支持）

## 0. 承重事实（已查证）

- skills CLI **无安装钩子**、安装动作 = git clone + 复制文件，**不执行**被装内容
  （其 exec/spawn 均为正则/自递归/启动 agent，无 postinstall 面）
- 真正的攻击窗口是**技能内容被 agent 加载进上下文**，不是落盘瞬间
- Python 标准库无文件系统监听：Windows 需 ctypes 调 `ReadDirectoryChangesW`，
  macOS 需 ctypes 调 FSEvents（`FSEventStreamCreate`）——两者均可纯标准库实现
- PyInstaller 6.22 可用；pystray/pywebview 是打包期依赖，不进源码依赖

## 1. 三件交付物

### 1a. `skill-radar add` 安全网关（装前拦截）

```
skill-radar add <skills-cli 的任何参数...>
  1. 解析目标 repo URL（从参数中提取，与 skills CLI 的 source 语法对齐）
  2. 浅克隆到临时目录 → run_engine 全引擎扫描
  3. 判定（复用 skill_report.install_verdict 的三分法）：
     - 拦截模式 --block：CRITICAL 或 漂移 → 拒绝并退出码 1，不转调安装
     - 警告模式（默认）：打印报告 + 安装建议，继续
  4. 通过后转调 `npx skills add <原参数>`（subprocess，透传退出码）
  5. 安装成功后自动对新增技能建快照基线（audit 增量）
- 模式持久化：--block 首次使用时询问并写入 config.yaml（gate_consent 复用）
- 非交互 + --block + CRITICAL → fail-closed 拒绝（与 scan --strict 一致）
- alias 加速器（README 一行）：alias skills='skill-radar add -- skills ...'
  注意：alias 形态下 skill-radar add 需处理 "add" 子命令透传（去重首个 add）
```

### 1b. 托盘守护客户端 SkillRadar Tray（v2.2 唯一 GUI 交付物，双平台）

```
架构：PyInstaller 单 exe/app
  ├─ 守护线程：目录监听（Win: ReadDirectoryChangesW / mac: FSEvents，纯 ctypes）
  │    盯注册表全部 roots；debounce 3s（写入稳定）；对变更技能增量扫描
  │    响应：警告模式=Toast+托盘徽标变色；拦截模式(+--quarantine 子开关,
  │    默认关)=Toast+移动到 ~/.skill-radar/quarantine/(附恢复说明)
  ├─ 托盘：pystray 图标（正常=墨蓝/告警=红/隔离=琥珀），菜单：打开界面/
  │    立即巡检/暂停守护/退出
  ├─ 界面：pywebview 窗口加载本地 HTML（见 §2），关闭窗口=缩托盘不退出
  └─ 数据：复用 ~/.skill-radar/snapshots.json + config.yaml（与 CLI 完全互通）
```

### 1c. 打包矩阵

| 交付物 | Windows | macOS |
|---|---|---|
| SkillRadarTray（托盘+界面+守护） | exe（PyInstaller onefile） | .app + .dmg（PyInstaller windowed） |
| CLI 全家桶（scan/audit/monitor/report/add） | 源码 + py 文件不变；exe 打包为 roadmap | 同左 |

源码仓库零依赖承诺不破：pystray/pywebview 只出现在 requirements-gui.txt
（构建期才安装），核心五件 .py 仍然纯标准库。

## 2. 客户端界面（frontend-ui-foundry · 冷调极简 Token）

设计语言：**冷调极简**（Linear/Vercel/Geist 系——开发者工具场景），
admin-dashboard 场景基线，双语（EN·中文）。

```css
/* 核心Token（OKLCH，完整套件内置于 app 内嵌 HTML） */
--color-primary: oklch(0.55 0.20 250);        /* 靛蓝 #4f46e5 */
--color-surface: oklch(0.99 0.005 240);       /* 近白 */
--color-on-surface: oklch(0.15 0.01 240);      /* 近黑 */
--color-error: oklch(0.55 0.20 25);
--color-success: oklch(0.65 0.18 145);
--color-warning: oklch(0.75 0.15 80);
/* 承诺度 Restrained：主色≤10%表面，大量留白，细线边框代替阴影 */
```

四屏结构（左 sidebar 240px + 主区，Data Table + Toast + Drawer，无嵌套卡片）：

1. **Overview 概览**：守护状态、监听根数、最近事件流、今日 NEW/DRIFT/BLOCK 计数
2. **Security 安全**：技能风险表（复用 guard 报告的安装建议列），CRITICAL 行内联
   红色徽章；行点击开右侧 Drawer 看 findings 明细 + --show-diff/accept 操作按钮
3. **Usage 用量**：复用 usage 报告数据，Top 条形图 + 明细表
4. **Settings 设置**：拦截/警告模式切换、roots 管理、quarantine 开关、
   "打开数据目录"按钮

反模式自检（anti-patterns.md）：无侧边色条、无渐变文字、无玻璃拟态默认、
无 hero-metric 大数字模板、模态不作为第一反应（用 Drawer）；动效只
transform/opacity、ease-out、150-300ms、尊重 prefers-reduced-motion；
正文 65-75ch、字号阶≥1.25、不用 Inter/Roboto/Arial（用系统栈：
Segoe UI/ SF Pro + 中文 PingFang/雅黑）。对比度 ≥4.5:1，触摸目标≥44pt。
界面语言跟随报告双语模式（EN · 中文并排）。

## 3. 跨平台要点

| 事项 | Windows | macOS |
|---|---|---|
| 目录监听 | ReadDirectoryChangesW（ctypes） | FSEvents（ctypes，需主 runloop 线程桥接） |
| Toast | PowerShell burntToast 兼容层或 pystray notify | osascript -e display notification |
| 托盘 | pystray（Win 图标 API） | pystray（NSStatusItem） |
| 自启（可选引导） | schtasks / 启动文件夹快捷方式 | launchd plist（Login Items） |
| 打包 | pyinstaller --onefile --windowed | pyinstaller --windowed → .app；hdiutil 出 dmg |
| 签名/公证 | 不做（roadmap；无证书） | 不做公证（roadmap；README 说明 Gatekeeper 右开） |

macOS FSEvents 回调需在 CFRunLoop 上跑：守护线程里 `CFRunLoopRun()`，
pystray/pywebview 各自已有主线程策略——实现计划里把"线程模型"列为独立任务，
这是本设计最难的接缝，先写伪代码再实现。

## 5. 威胁模型增补

- 托盘守护自身不受被扫内容影响：监听回调只做"路径入队"，扫描在工作线程，
  扫描异常不崩守护（try/except 全包+日志）
- quarantine 移动是唯一改变文件系统的动作：仅限注册 roots 内路径（防路径遍历
  注入），移动前二次校验路径前缀
- Toast 文案过 _sanitize（与报告一致）
