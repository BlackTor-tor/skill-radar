## 二、缺陷记录

### D-1 打包 exe 的 UI 窗口加载失败（ERR_FILE_NOT_FOUND）——已修复并复测 ✅

- **现象（修复前）**：exe 启动后 pywebview 窗口显示「未找到文件 ERR_FILE_NOT_FOUND」，四屏/Drawer 均未渲染（截图 `evidence/task8-desktop.png`）。
- **守护不受影响**：托盘常驻、目录监听、扫描、快照、隔离、Toast 子进程调用全部正常（验收项 1/2/2c 全过）。
- **根因（已实证）**：`tray/app.py` 的 `BASE = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))` 未适配 frozen 形态。onefile 入口脚本在 `_MEIPASS` 根下展开为 `app.py`，故 BASE 解析到 `_MEIPASS` 的**父目录**（`%TEMP%`），`_index_url()` 指向不存在的 `%TEMP%/tray/web/index.html`；而被 import 的 `tray/daemon.py` 的 `__file__` 为 `_MEIPASS/tray/daemon.py`，base 解析正确，rules 正常加载——与「守护正常、UI 白屏」的实测完全一致。
  - 证据：修复前运行实例的解压目录 `%TEMP%/_MEI572202、_MEI596362、_MEI839962` 内 `tray/web/index.html` 存在（spec datas 已正确打包），而 `%TEMP%/tray/web/index.html` 不存在（即窗口实际请求的路径）。
- **修复（第 1 轮，commit `fix(tray): frozen resource base + in-process guard actions; exe UI re-verified`）**：
  1. `tray/app.py` 新增 `_res_base()`：frozen 优先取 `sys._MEIPASS`，源码运行回退仓库根；
  2. 同源接缝顺手修：`JsBridge._run_guard` 由 subprocess（frozen 下 `sys.executable` 是托盘 exe 本体、包内无 skill_guard.py，会重启托盘而非执行命令）改为进程内调 `sg.main(args)`（`redirect_stdout/stderr` 捕获输出；SystemExit/异常不炸壳层），补 2 条测试（`tests/tray/test_app_smoke.py`：`test_res_base_frozen_vs_source`、`test_run_guard_in_process`），回归 237 passed, 2 skipped；
  3. `python build_tray.py` 重打包（352,823,331 B）。
- **复测（✅ 通过）**：重启 exe → 2 进程正常 → 桌面截图 `evidence/task8-desktop-postfix.png` 显示 **Overview 屏完整渲染**：侧栏四项（Overview/Security/Usage/Settings）、「运行中 Running」、「5 监听根 Roots」（与实际存在的根数一致）、今日漂移/拦截 0、最近事件流表头——不再 ERR_FILE_NOT_FOUND。截图佐证下，原被阻塞的「四屏渲染」目视项升级为「渲染已证实，切换/Drawer 交互仍 ⏳人工」。
