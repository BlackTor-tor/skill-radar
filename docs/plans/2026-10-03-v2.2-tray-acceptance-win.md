## 二、缺陷记录

### D-1 打包 exe 的 UI 窗口加载失败（ERR_FILE_NOT_FOUND）⚠️

- **现象**：exe 启动后 pywebview 窗口显示「未找到文件 ERR_FILE_NOT_FOUND」，四屏/Drawer 均未渲染（截图 `evidence/task8-desktop.png`）。
- **守护不受影响**：托盘常驻、目录监听、扫描、快照、隔离、Toast 子进程调用全部正常（验收项 1/2/2c 全过）。
- **根因（已实证）**：`tray/app.py` 的 `BASE = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))` 未适配 frozen 形态。onefile 入口脚本在 `_MEIPASS` 根下展开为 `app.py`，故 BASE 解析到 `_MEIPASS` 的**父目录**（`%TEMP%`），`_index_url()` 指向不存在的 `%TEMP%/tray/web/index.html`；而被 import 的 `tray/daemon.py` 的 `__file__` 为 `_MEIPASS/tray/daemon.py`，base 解析正确，rules 正常加载——与「守护正常、UI 白屏」的实测完全一致。
  - 证据：当前运行实例的解压目录 `%TEMP%/_MEI572202、_MEI596362、_MEI839962` 内 `tray/web/index.html` 存在（spec datas 已正确打包），而 `%TEMP%/tray/web/index.html` 不存在（即窗口实际请求的路径）。
- **建议修复**：`app.py` 顶部 BASE 计算加 frozen 分支，例如
  `BASE = getattr(sys, "_MEIPASS", None) or os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`（`tray/web`、`rules` 均已按 `_MEIPASS` 相对路径打包，`SkillRadarTray.spec` datas 无需改动）。建议入 v2.2 修一版后重打包复测人工项。
